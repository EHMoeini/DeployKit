# دستورالعمل ۰۰: معماری کلان، قوانین قطعی و پروتکل اجرایی AI Agent

این سند نقشه راه بنیادین، محدودیت‌های غیرقابل مذاکره، ساختار مخزن و پروتکل گام‌به‌گام را برای **AI Agent** مشخص می‌کند. تمام دستورالعمل‌های این پوشه (`00` تا `14`) به عنوان یک سیستم واحد و پیوسته عمل می‌کنند و باید دقیقاً به ترتیب عددی اجرا شوند.

---

## ۱. هدف و چشم‌انداز سیستم

پیاده‌سازی و استقرار کامل یک سامانه تحت وب مدرن، کاملاً **Stateless** در لایه اپلیکیشن، مقیاس‌پذیر به صورت افقی (Horizontal Scaling)، فرانت‌اند تک‌صفحه‌ای (True SPA) ساختاریافته و ماژولار، پایگاه داده ماندگار PostgreSQL، پروکسی معکوس Traefik با SSL خودکار، کانتینرسازی استاندارد Docker، ارکستراسیون **Docker Swarm**، پایپ‌لاین CI/CD در GitHub Actions و مدیریت زیرساخت با Ansible.

---

## ۲. قوانین مطلق و محدودیت‌های غیرقابل تغییر (Non-Negotiable Constraints)

هرگونه نقض قوانین زیر، کل فرآیند توسعه را نامعتبر می‌سازد:

1. **ممنوعیت مطلق Redis:**
   - در هیچ لایه‌ای (نه برای Session، نه Cache، نه Token Blacklist و نه صف Job) نباید از Redis یا سرویس‌های مشابه استفاده شود. تمام ماندگاری‌ها بر عهده PostgreSQL است.
2. **ممنوعیت مطلق Nginx:**
   - از Nginx نباید استفاده شود (نه به عنوان Reverse Proxy سیستم و نه به عنوان وب‌سرور داخل کانتینر Frontend).
3. **انحصار Traefik:**
   - تنها نقطه ورود عمومی به سیستم و تنها Reverse Proxy مجاز، **Traefik** است.
4. **الزام معماری SPA واقعی (True SPA):**
   - هیچ‌گونه رندر سمت سرور (SSR) یا تولید سایت استاتیک (SSG) مجاز نیست. رندر صفحات منحصراً در مرورگر کلاینت انجام می‌شود.
5. **ممنوعیت Sticky Session:**
   - سرویس Backend باید ذاتاً و کاملاً Stateless باشد. درخواست‌های متوالی یک کاربر ممکن است توسط Replicaهای مختلف Backend پاسخ داده شوند بدون اینکه خطایی رخ دهد.
6. **تفکیک قطعی ساخت (Build) از استقرار (Deploy):**
   - سرور Production هرگز کد منبع را کامپایل یا Build نمی‌کند. ایمیج‌ها در GitHub Actions، Docker Hub یا هر Container Registry دیگر ساخته شده و روی سرور صرفاً Pull می‌گردند (پشتیبانی مستقیم از متغیرهای `backend_image` و `frontend_image` یا الگوی GHCR).
7. **ممنوعیت درج Secretها در کد و Git:**
   - هیچ رمز عبور، کلید خصوصی، توکن یا کانفیگ حساسی نباید در سورس‌کد، Dockerfile یا مخزن Git ثبت شود. متغیرها از طریق فایل Inventory (`ansible/inventory/production/hosts.yml`)، تولید خودکار و امن Ansible (`lookup('password')`) یا Ansible Vault خارج از گیت تأمین می‌شوند تا استقرار برای کاربر بدون پیچیدگی و امن باشد.
8. **دروازه تأیید انسانی (Human Approval Gates):**
   - برای اقدامات پرریسک (مانند اعمال تغییرات دیسک در `storage-apply.yml`، تغییر قوانین SSH فایروال، اجرای Migrationهای مخرب یا بازنویسی دیتابیس در Disaster Recovery) Agent باید طرح و خطرات را به کاربر نمایش داده و تأیید صریح دریافت کند.
9. **تغییرات فقط از طریق Ansible با رویکرد استقرار تک‌دستوری (Turn-key Zero-Touch Deployment):**
   - هیچ دستور تغییری نباید دستی روی سرور اجرا شود. کل فرآیند از آماده‌سازی سرور خام (نصب خودکار پایتون ۳)، نصب داکر، راه‌اندازی Swarm، ساخت شبکه‌ها، SSL خودکار، استقرار استک‌ها، Migration، Rollback و Teardown همگی باید تنها با اجرای یک پلی‌بوک جامع (`ansible-playbook -i inventory/production/hosts.yml playbooks/site.yml` یا اسکریپت `./deploy.sh`) قابل پیاده‌سازی باشد، به گونه‌ای که هر کاربری صرفاً با تغییر آی‌پی سرور در Inventory بتواند استقرار را به سرانجام برساند.
   - **استثنای کنترل‌شده:** رول `watchtower` یک عامل به‌روزرسانی خودکار را از طریق Ansible نصب و مدیریت می‌کند تا تصاویر جدید را با rolling update اعمال کند. این عامل فقط از طریق قفل مشترک و پرچم توقف با Ansible هماهنگ می‌شود، همیشه با Ansible قابل غیرفعال‌سازی/حذف است و هیچ تغییر دستی روی سرور محسوب نمی‌شود.

## ۳. ساختار استاندارد مخزن واحد (Monorepo Layout)

ساختار نهایی مخزن پروژه باید دقیقاً مطابق درخت زیر پیاده‌سازی شود:

```text
project-root/
├── .github/
│   └── workflows/
│       └── docker-publish.yml      # پایپ‌لاین ساخت و انتشار ایمیج در GHCR
├── frontend/                       # کد منبع SPA (کامپوننت‌ها، ویوها، روتر)، سرور استاتیک و Dockerfile
│   ├── src/
│   ├── public/
│   ├── server.js                   # سرور استاتیک اختصاصی و سبک (بدون Nginx)
│   ├── entrypoint.sh               # تولید /config.js زمان اجرا و اعمال مجوزها
│   ├── package.json
│   ├── vite.config.js
│   └── Dockerfile
├── backend/                        # کد منبع API، مدیریت احراز هویت، Migrationها و Dockerfile
│   ├── src/
│   │   ├── config/
│   │   ├── controllers/
│   │   ├── middleware/
│   │   ├── models/
│   │   ├── routes/
│   │   ├── services/
│   │   └── index.js
│   ├── migrations/                 # اسکریپت‌های مستقل Database Migration
│   ├── package.json
│   └── Dockerfile
├── scripts/                        # اسکریپت‌های پشتیبان‌گیری، بازیابی و اعتبارسنجی دیتابیس
│   ├── backup_postgres.sh
│   ├── verify_backup.sh
│   ├── test_restore_monthly.sh
│   └── restore_disaster.sh
├── ansible/                        # چارچوب جامع مدیریت زیرساخت و استقرار
│   ├── ansible.cfg
│   ├── requirements.yml
│   ├── deploy.sh                   # اسکریپت اجرای تک‌دستوری دپلوی در پوشه انسیبل
│   ├── inventory/
│   │   ├── development/
│   │   ├── staging/
│   │   └── production/             # شامل hosts.yml دو زبانه و ساده‌سازی‌شده
│   ├── playbooks/
│   ├── roles/
│   └── vault/
├── deploy.sh                       # اسکریپت اصلی اجرای تک‌دستوری در ریشه پروژه
├── docker-compose.yml              # استک Docker Swarm برای Production/Staging (۳ فرانت / ۴ بک‌اند)
├── docker-compose.local.yml        # فایل اجرای محلی و تست مقیاس‌پذیری (شامل ساخت محلی و Traefik محلی)
├── .env.example                    # الگوی متغیرهای محیطی
├── .gitignore
└── docs/                           # مستندات نهایی معماری، استقرار، ریکاوری و عملیات
```

## ۵. پروتکل اجرایی AI Agent

1. **یک گام در هر زمان:** هرگز دستورالعمل‌های چند فایل را هم‌زمان اجرا نکن. پس از اتمام هر فایل، چک‌لیست اعتبارسنجی آن را بررسی کرده و سپس به فایل بعدی برو.
2. **بررسی پیش‌نیازها:** پیش از شروع هر دستورالعمل، اطمینان حاصل کن که تمام پیش‌نیازهای اعلام‌شده در ابتدای آن فایل موجود و سالم هستند.
3. **تولید کدهای کامل و بدون Placeholder:** از قرار دادن کدهای ناقص، توضیحات ناقص مانند `// TODO` یا تکه کدهای موقت خودداری کن. تمام کدها، اسکریپت‌ها و کانفیگ‌ها باید آماده اجرا در محیط واقعی باشند.
4. **ثبت وضعیت و لاگ:** هرگونه خطا در زمان اجرا را به دقت گزارش داده و پیش از ادامه مسیر برطرف نما.
