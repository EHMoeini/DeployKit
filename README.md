## ۱. معرفی و اصول معماری

هدف این پروژه ارائه یک پایپ‌لاین تولیدی واقعی بدون اضافه کردن ابزارهای غیرضروری است؛ معماری سامانه بر پایه کانتینرهای مستقل، احراز هویت توزیع‌شده بدون وضعیت و کمترین بار عملیاتی طراحی شده است.

### شفاف‌سازی نقش هوش مصنوعی (AI)
در این سامانه هیچ مدل زبانی یا سرویس هوش مصنوعی تعبیه‌شده‌ای وجود ندارد؛ هوش مصنوعی صرفاً در نقش دستیار کدنویسی برای طراحی ساختار اولیه استایل‌های بصری و ایده‌پردازی کامپوننت‌ها به کار رفته است و در انتهای راهنما، افزودن قابلیت‌های AI به‌عنوان تمرین به دانشجویان پیشنهاد می‌شود.

### طراحی رابط کاربری (Liquid Glass)
رابط کاربری کلاینت یک وب‌اپلیکیشن تک‌صفحه‌ای (SPA) جاوااسکریپتی بدون وابستگی به فریم‌ورک‌های سنگین است که از سبک طراحی شیشه‌ای مایع (Dark Obsidian Theme، پس‌زمینه‌های بلورین مات و نمایشگر زنده پاد پاسخ‌دهنده) بهره می‌برد.

## ۲. مفاهیم کلیدی و معماری سیستم

### این پروژه چه چیزی را آموزش می‌دهد؟
هر مفهوم نظری در این پروژه به صورت مستقیم در فایل‌های کد منبع پیاده‌سازی شده و قابل مشاهده است:

- **JWT (JSON Web Token):** ساخت، امضا و رمزگشایی توکن هویت ➔ `backend/src/services/auth.service.js`
- **احراز هویت بدون وضعیت (Stateless Auth):** اعتبارسنجی مستقل درخواست‌ها بدون سشن در رم سرور ➔ `backend/src/middleware/auth.middleware.js`
- **حفاظت ضد جعل (CSRF Protection):** هماهنگی کوکی امن با هدر اعتبارسنجی ➔ `backend/src/middleware/auth.middleware.js` و `frontend/src/services/api-client.js`
- **پروکسی معکوس (Reverse Proxy):** مسیریابی ترافیک به سرویس‌ها با Traefik v3 ➔ `docker-compose.local.yml` و `traefik/docker-compose.yml`
- **گواهی امنیتی خودکار (SSL/TLS):** مدیریت گواهی Let's Encrypt و تنظیم دسترسی acme.json ➔ `traefik/docker-compose.yml` و `scripts/setup-traefik.sh`
- **توزیع بار (Load Balancing):** چرخش درخواست‌ها بین رپلیکاهای کانتینری ➔ `docker-compose.yml` و `docker-compose.local.yml`
- **زیرساخت به‌صورت کد (IaC):** مدیریت خودکار سرور و سرویس‌ها با Ansible ➔ `ansible/playbooks/site.yml` و `ansible/roles/`
- **پایپ‌لاین انتشار پیوسته (CI/CD):** ساخت، تگ‌گذاری و انتشار خودکار ایمیج در GHCR ➔ `.github/workflows/docker-publish.yml`
- **پشتیبان‌گیری پایگاه داده (Backup & DR):** بکاپ‌گیری با قفل اتمیک و سنجش هش ➔ `scripts/backup_postgres.sh` و `scripts/verify_backup.sh`

### دیاگرام مسیر درخواست (Request Flow)

```text
┌──────────────────────┐
│  مرورگر کلاینت       │
│  (Client Browser)    │
└──────────┬───────────┘
           │ HTTPS (443) / HTTP (80)
           ▼
┌──────────────────────┐
│     Traefik v3       │  ◄── مدیریت خودکار گواهی Let's Encrypt
│ (Reverse Proxy & LB) │  ◄── توزیع بار (Round-Robin) بین رپلیکاها
└──────┬────────┬──────┘
       │        │
   Path: /   Path: /api/*
       │        │
       ▼        ▼
┌───────────┐  ┌─────────────────────────┐
│ Frontend  │  │   Backend Replicas      │
│   (SPA)   │  │ (Stateless API + JWT)   │
└───────────┘  └────────────┬────────────┘
                            │ Connection Pool (5432)
                            ▼
               ┌─────────────────────────┐
               │    PostgreSQL 16        │
               │ (Users & Refresh Tokens)│
               └─────────────────────────┘
```

### چرا این تصمیم‌ها؟ (Design Decisions)
- **چرا Redis نداریم؟** برای حذف پیچیدگی عملیاتی سرور؛ با احراز هویت بدون وضعیت JWT، نیازی به ذخیره سشن در رم نیست و ردیابی توکن‌ها مستقیماً با ایندکس سبک در دیتابیس صورت می‌گیرد.
- **چرا Stateless؟** کانتینرهای بک‌اند هیچ وضعیتی در حافظه محلی ذخیره نمی‌کنند و در هر لحظه می‌توان آنها را بدون قطع نشست‌های فعال کاربران ریستارت کرد یا تعداد رپلیکاها را افزایش داد.
- **چرا Traefik؟** برخلاف وب‌سرورهای سنتی، Traefik به فایل کانفیگ استاتیک وابسته نیست و کانتینرهای داکر را به صورت زنده کشف کرده و گواهی رایگان SSL صادر می‌کند.
- **چرا Docker Swarm؟** سوئرم سبک‌ترین راهکار ارکستراسیون چندنودی است که بدون نیاز به رم سنگین و پیچیدگی‌های Kubernetes، چرخه ارتقای روان (Rolling Update) را فراهم می‌آورد.

### واژه‌نامه مختصر (Glossary)
- **JWT:** توکن فشرده امضاشده حاوی هویت کاربر که در هدر درخواست ارسال می‌شود.
- **Refresh Token:** رشته رمزنگاری‌شده در کوکی امن `HttpOnly` برای تمدید JWT منقضی‌شده.
- **CSRF:** حمله وب برای ارسال ناخواسته دستورات؛ با توکن `x-csrf-token` در هدر مهار می‌شود.
- **Reverse Proxy:** سرور واسط در مرز شبکه برای مسیریابی و تفکیک ترافیک پابلیک از سرویس‌های داخلی.
- **Replica:** نسخه‌های یکسان و فعال از یک کانتینر برای پایداری و تقسیم ترافیک.
- **Load Balancer:** ماژول توزیع‌کننده ترافیک ورودی بین رپلیکاهای کانتینری.
- **Migration:** اسکریپت‌های نسخه‌بندی‌شده پایگاه داده برای تغییر ایمن جداول بدون اتلاف داده.
*(برای توضیحات بیشتر به [واژه‌نامه کامل docs/glossary.md](docs/glossary.md) مراجعه کنید).*

### مرحله ۱: اجرای پایگاه داده و بک‌اند لوکال
پایگاه داده PostgreSQL، اسکریپت مایگریشن خودکار و سرویس بک‌اند را اجرا کنید:

```bash
docker compose -f docker-compose.local.yml up -d postgres migrate backend
```

> ⚠️ **هشدار امنیتی:** رمزهای عبور و `JWT_SECRET` پیش‌فرض در فایل `docker-compose.local.yml` فقط برای محیط توسعه است؛ در محیط واقعی از کلیدهای تصادفی قوی استفاده کنید.

**خروجی مورد انتظار:**
کانتینرهای دیتابیس و بک‌اند با وضعیت `Up` و کانتینر مایگریشن با وضعیت `Exited (0)` خاتمه می‌یابد. با دستور زیر وضعیت را مشاهده کنید:
```bash
docker compose -f docker-compose.local.yml ps
```
پاسخ اندپوینت سلامت بک‌اند را روی پورت 3000 بسنجید:
```bash
curl -s http://localhost:3000/api/health
# خروجی: {"status":"ok","timestamp":"..."}
```

### مرحله ۲: دریافت توکن JWT با curl
احراز هویت بدون وضعیت را با ثبت‌نام و دریافت توکن از طریق اسکریپت آماده یا دستور مستقیم curl آزمایش کنید:

```bash
./scripts/demo_login.sh http://localhost:3000
```
*(یا با دستور curl مستقیم):*
```bash
curl -s -X POST http://localhost:3000/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"student_1","password":"SecretPassword123!"}'
```

> ⚠️ **هشدار امنیتی:** توکن JWT کلید احراز هویت شماست؛ هرگز آن را در مخازن عمومی ذخیره نکنید و در لاگ‌های عمومی لاگ نزنید.

**خروجی مورد انتظار:**
یک رشته متنی طولانی که با حروف `eyJ` آغاز می‌شود (نشانه استاندارد هدر کدگذاری‌شده Base64 در JWT) به همراه کد وضعیت `201` یا `200` چاپ می‌گردد:
```json
{"user":{"id":1,"username":"student_1"},"accessToken":"eyJhbGciOiJIUzI1NiIs...","csrfToken":"..."}
```

### مرحله ۴: افزودن Traefik و بررسی مسیریابی یکپارچه
پروکسی معکوس Traefik را برای تجمیع پورت‌ها، لودبالانسینگ و مسیردهی یکپارچه فعال کنید:

```bash
docker compose -f docker-compose.local.yml up -d traefik
```

> ⚠️ **هشدار امنیتی:** داشبورد بدون پسورد Traefik (`:8081`) صرفاً برای مانیتورینگ در محیط توسعه فعال است و نباید در اینترنت عمومی باز بماند.

**خروجی مورد انتظار:**
Traefik روی پورت استاندارد `80` ترافیک را مدیریت می‌کند. اکنون کل سامانه (فرانت‌اند روی `/` و بک‌اند روی `/api`) بدون نیاز به ذکر پورت باز می‌شود:
- رابط کاربری: `http://localhost`
- وضعیت سلامت: `curl -s http://localhost/api/health` ➔ `{"status":"ok"}`
- داشبورد Traefik: `http://localhost:8081`

حالا به [مرحله ۵: استقرار روی سرور (VPS) با Ansible](#مرحله-۵-استقرار-روی-سرور-vps-با-ansible) بروید.

### مرحله ۵: استقرار روی سرور (VPS) با Ansible
استقرار روی سرور عملیاتی از طریق ۴ دستور ساده انسیبل انجام می‌گیرد؛ پیش از اجرا، آیپی سرور را در `ansible/inventory/production/hosts.yml` مشخص کنید:

> ⚠️ **هشدار امنیتی:** رمزهای عملیاتی و سکرت‌های تولید را درون `vault` رمزنگاری کنید و کلیدهای اصلی را هرگز در گیت کامیت نکنید.

1. **استقرار کامل سامانه (Deploy):**
   ```bash
   ansible-playbook -i ansible/inventory/production/hosts.yml ansible/playbooks/site.yml
   ```
2. **بازگشت به نسخه پایدار قبلی (Rollback):**
   ```bash
   ansible-playbook -i ansible/inventory/production/hosts.yml ansible/playbooks/rollback.yml
   ```
3. **حذف سرویس‌ها بدون اتلاف داده (Teardown):**
   ```bash
   ansible-playbook -i ansible/inventory/production/hosts.yml ansible/playbooks/teardown.yml
   ```
4. **مشاهده وضعیت کانتینرها در سرور (Status):**
   ```bash
   ssh deployer@<SERVER_IP> "docker service ls && docker stack ps portal"
   ```

*(برای مشاهده جزئیات خودکارسازی، قفل‌های هم‌زمانی و مقایسه دیجست به [راهنمای پیشرفته docs/advanced.md](docs/advanced.md) مراجعه کنید).*

### چطور مطمئن شوم کار می‌کند؟ (Health Checks)
سلامت بخش‌های مختلف را با دستورات زیر بسنجید:

1. **وضعیت کانتینرها:**
   ```bash
   docker compose -f docker-compose.local.yml ps
   ```
2. **سلامت عمیق بک‌اند و ارتباط پایگاه‌داده:**
   ```bash
   curl -s http://localhost/api/health/ready
   # خروجی: {"status":"ready","db":"connected","latencyMs":...}
   ```
3. **بررسی گواهی SSL در سرور:**
   ```bash
   curl -Iv https://your-domain.com/api/health
   # در خروجی خطوط: SSL connection using TLS... و Server certificate تایید می‌شود.
   ```

### چطور ببینم Load Balancing کار می‌کند؟
در محیط سرور چند رپلیکا هم‌زمان اجرا می‌شوند و پاسخ هر درخواست شناسه پاد مجزایی دارد:

```bash
# ۱. مشاهده لیست رپلیکاهای در حال اجرای سرویس بک‌اند:
docker service ps portal_backend

# ۲. تست چرخش درخواست‌ها بین رپلیکاها (Round-Robin):
for i in {1..5}; do curl -sI http://localhost/api/health | grep -i x-pod-id; done
```
**خروجی مورد انتظار:** با هر فراخوانی، شناسه متفاوتی (نظیر `portal_backend.1...` و `portal_backend.2...`) در هدر `x-pod-id` چاپ می‌شود که گواه توزیع عادلانه ترافیک است.

## ۵. اشکالات و اشتباهات رایج

### ۸ اشتباه بزرگ امنیتی و اجرایی
1. **قرار دادن `JWT_SECRET` در کد منبع:** منجر به جعل هویت کاربران توسط هر کسی که به کد دسترسی دارد؛ همیشه از متغیر محیطی استفاده کنید.
2. **ذخیره Refresh Token در `localStorage`:** در برابر حملات XSS آسیب‌پذیر است؛ حتماً باید در کوکی امن با فلگ‌های `HttpOnly` و `SameSite` ذخیره شود.
3. **پشتیبان‌گیری بدون تست ری‌استور:** تا زمانی که بازگردانی بکاپ تست نشده باشد، عملاً بکاپی وجود ندارد.
4. **باز گذاشتن پورت دیتابیس به اینترنت:** پورت 5432 دیتابیس هرگز نباید به بیرون منتشر شود و باید صرفاً در شبکه داخلی داکر باشد.
5. **اجرای کانتینر با دسترسی روت (`root`):** در صورت رخنه‌پذیری کد، امکان نفوذ به هاست فراهم می‌شود؛ کانتینرها باید با یوزر محدود (مانند `USER node`) اجرا شوند.
6. **نادیده گرفتن Rate Limit روی `/login`:** سرور را در برابر حملات محروم‌سازی سرویس (DoS) و Brute-Force بی‌پناه می‌گذارد.
7. **فراموش کردن دسترسی 600 برای `acme.json`:** نرم‌افزار Traefik اگر دسترسی فایلی غیر از `0600` ببیند، گواهی SSL صادر نمی‌کند.
8. **استفاده از تگ `latest` در Production:** قابلیت ردیابی و Rollback مطمئن را سلب می‌کند؛ همیشه ایمیج‌ها را با هش کامیت یا شماره نسخه استقرار دهید.

*(مطالعه راهنما و توضیحات بیشتر در [docs/common-pitfalls.md](docs/common-pitfalls.md)).*

### عیب‌یابی سریع (Troubleshooting)

- **علامت:** صفحه با خطای SSL باز نمی‌شود ➔ **علت:** دسترسی نامعتبر کلیدها یا بسته بودن پورت 80/443 ➔ **راه‌حل:** اجرای `chmod 600 acme.json` و بررسی فایروال سرور با `ufw status`.
- **علامت:** دریافت خطای `502 Bad Gateway` ➔ **علت:** آماده نبودن بک‌اند یا عدم عضویت در شبکه Traefik ➔ **راه‌حل:** بررسی لاگ کانتینر با `docker compose logs backend` و سلامت مایگریشن‌ها.
- **علامت:** دریافت خطای `403 Forbidden: Invalid CSRF token` ➔ **علت:** عدم ارسال هدر `x-csrf-token` در متدهای POST ➔ **راه‌حل:** دریافت مقدار توکن از کوکی و افزودن آن به هدر درخواست.
- **علامت:** دیتابیس اجرا نمی‌شود یا کرش می‌کند ➔ **علت:** خطای دسترسی پوشه داده‌ها یا پر بودن دیسک ➔ **راه‌حل:** بررسی حجم خالی دیسک با `df -h` و مشاهده لاگ با `docker compose logs postgres`.

## ۶. ادامه مسیر و اسناد پیشرفته

برای تسلط کامل بر مباحث عملیاتی، پایپ‌لاین‌های انتشار و مدیریت بحران، اسناد زیر را دنبال کنید:

- **[کتابچه عملیات و راهبری (docs/runbook_and_operations.md)](docs/runbook_and_operations.md):** راهنمای جامع فرمان‌های روزمره، مانیتورینگ و لاگ‌گیری.
- **[طرح بازیابی فاجعه (docs/disaster_recovery.md)](docs/disaster_recovery.md):** دستورالعمل‌های گام‌به‌گام بازیابی سرور و پایگاه‌داده هنگام بروز حوادث جدی.
